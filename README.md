# На что жалуются пользователи ИИ-инструментов для кода

Исследование 2 699 публичных обращений к шести открытым ИИ-инструментам для программирования: Codex, Cline, Gemini CLI, Roo Code, Continue и Aider. Обращения собраны с GitHub, размечены ИИ-агентом на GigaChat, качество агента измерено на проверочной выборке.

Данные выгружены 10 октября 2026.

## Что получилось

- **77% обращений написаны людьми и по делу** (2 080 из 2 699). Ещё 19% создают сами программы при сбое, 4% мусор.
- **У каждого инструмента своя главная тема жалоб:**

| Инструмент | Главная тема | Доля среди осмысленных обращений |
|---|---|---|
| Codex | Песочница и безопасность | 22% |
| Cline | Интерфейс | 24% |
| Roo Code | Модели | 26% |
| Gemini CLI | Интеграции | 21% |
| Continue | Интеграции | 21% |
| Aider | Поведение агента | 19% |

- **У Codex один сбой даёт 23% всех жалоб:** 177 обращений из 784 за три дня описывают один и тот же отказ песочницы на Windows. По этой находке написана спека на фичу.
- **Простые метрики обманывают.** У Aider 97% закрытых обращений закрыты за сутки, но это дубли автоматических отчётов. У Continue обращения закрывает таймер, а не решение. Считать «сколько закрыто и как быстро» бессмысленно, нужно читать тексты.

## Как это устроено

1. `fetch_issues.py` выгружает обращения через открытый интерфейс GitHub в базу SQLite: таблицы `issues`, `labels`, `repos`.
2. `classify.py` размечает каждое обращение по двум признакам:
   - тип: баг, просьба о фиче, вопрос, мусор;
   - тема: одна из двенадцати, от установки до оплаты.
   Автоматические отчёты о падениях определяются правилом по заголовку и в модель не отправляются.
3. `eval.py` сравнивает ответы агента с проверочной выборкой и считает долю верных.
4. `export_labels.py` собирает итоговую разметку в `labeled_issues.json`.

## Как проверяли агента

Агент проверен на 100 обращениях с известными ответами, по 16–17 из каждого инструмента (`gold_labels.json`).

| Шаг | Тип верен | Тема верна | Оба верны |
|---|---|---|---|
| Первая инструкция, GigaChat-2 Lite | 85% | 44% | 40% |
| Вторая инструкция, GigaChat-2 Lite | 81% | 53% | 48% |
| Вторая инструкция, GigaChat-2 Pro | 88% | 69% | 62% |
| Третья инструкция, GigaChat-2 Max | 94% | 77% | 74% |

Что из этого следует:

- Замена модели дала больше, чем правка инструкции. На модели Pro третья инструкция не лучше второй: 67% против 69%.
- Младшей модели длинная инструкция вредит: 48% с третьей против 53% со второй.
- Часть ошибок оказалась не ошибками модели, а пересечением тем. Модель сама отвечала темой «настройки», которой не было в списке. После разбора список тем изменён, это и есть третья инструкция.
- Выборка маленькая, погрешность каждой цифры около 10 процентных пунктов.

## Ограничения

- По каждому инструменту взяты последние обращения, поэтому периоды разные: три дня у Codex и семь месяцев у Aider. Сравнивать можно доли внутри инструмента, а не количества.
- Тему агент определяет верно в 77% случаев, поэтому доли по темам приблизительные.
- Инструкцию трижды правили на одной и той же проверочной выборке, так что итоговая точность на ней немного завышена.
- Сбой песочницы Codex найден поиском по тексту ошибки, причина сбоя взята из описаний пользователей.

## Как запустить

Нужен Python 3 и `curl`, сторонние библиотеки не используются.

```
python3 fetch_issues.py                  # выгрузка с GitHub в issues.db
echo "GIGACHAT_KEY=ваш_ключ" > .env      # ключ авторизации GigaChat API
python3 classify.py --gold --prompt v3 --model GigaChat-2-Max   # проверочная выборка
python3 eval.py                          # точность агента
python3 classify.py --all --prompt v3 --model GigaChat-2-Max    # все обращения
python3 export_labels.py                 # итоговый файл
```

Без токена GitHub отдаёт 60 запросов в час, этого хватает на выгрузку по умолчанию.
